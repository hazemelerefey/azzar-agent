# Core OTA local E2E (packaged state)

Build an arm64 shell with a built-in core (v1) on this machine, then publish a renderer-only update (v2, reload) and a main-process change (v3, relaunch) through a local feed. Finally verify tamper rejection and boot rollback.
Defaults to the Canary channel (macOS Stable only does full-package upgrades). Use `CORE_OTA_TEST_CHANNEL` and `CORE_OTA_TEST_PRODUCT` to isolate test instances; `CORE_OTA_TEST_PORT` / `CORE_OTA_TEST_CDP_PORT` avoid clashing with existing services.
The v1 to v4 labels here are test version numbers. The transport protocol is schemaVersion 4 throughout, using the `<channel>/<appVersion>/core-v4/<platform>` feed and HTTP Range. The built-in business code lives in `core.asar`; the CLI lives in `core.asar.unpacked/cli/dist/index.js`. Run all commands from `apps/desktop/`.

All artifacts land in `release/core-ota-e2e/`: `priv.pem`/`pub.pem`, `app/` (the packaged result), `core-v1..v3/`, `feed/`.
The app name is fixed as `azzar-core-ota-e2e`, userData is at `~/Library/Application Support/azzar-core-ota-e2e`, and logs are at `~/Library/Logs/azzar-core-ota-e2e/main.log`, so it never interferes with the development instance.

## Manual pack integration verification

```bash
bun run test:core-ota
```

This verification performs real zstd compression, packaging, and disk staging. It covers cross-version reuse, a 401-file incremental update, Range, patches, and corruption rejection.
Run it manually only when the OTA protocol changes or before a release. It is not part of the default `test` / PR CI. The standalone configuration allows up to 30 seconds per item.
It verifies correctness and does not measure performance, so it is not a benchmark.

## 1. Build v1 (once, about 10 minutes)

```bash
node scripts/core-ota-test/run.mjs keys
node scripts/core-ota-test/run.mjs build # skips build:main if dist/ exists; packages with --dir, no signing or notarization
```

`build` temporarily renames `package.json` name/version to `azzar-core-ota-e2e`/`1.0.0` (Electron derives userData from the name), and `run.mjs restore` reverts it afterwards.
The shell's `abi.json` and the built-in core's signature manifest (seq 0) are generated by `beforePack` in `electron-builder.mjs`;
r0 in `feed/` is byte-identical to the built-in core.

## 2. Renderer-only update (reload)

```bash
node scripts/core-ota-test/run.mjs v2      # adds a red "CORE V2" badge to index.html, seq 1
node scripts/core-ota-test/run.mjs serve & # http://127.0.0.1:8787
node scripts/core-ota-test/run.mjs reset   # clears userData/logs
node scripts/core-ota-test/run.mjs launch  # RENDERER_OTA_CHECK_DELAY=3000
```

Expected: the log shows `Core OTA staged {"applyMode":"reload",...}`; clicking "Refresh" on the toast (or waiting 5 minutes idle) shows `CORE V2` in the top-right corner of the window;
`run.mjs state` shows `current: "1.0.0-core.1"`.

## 3. Main-process change (relaunch)

```bash
node scripts/core-ota-test/run.mjs v3 # appends console.log('core v3') to dist/main/index.js, seq 2
```

Trigger a check inside the app (or wait for the 60-minute timer). The log shows `applyMode":"relaunch"`, the toast offers "Restart now",
and after restart the log starts with `core v3`. `state` shows `current: "1.0.0-core.2"` and the shell log shows `source: external`.

## 4. Tamper rejection

```bash
node scripts/core-ota-test/run.mjs kill
node scripts/core-ota-test/run.mjs tamper # modifies cores/1.0.0-core.2/dist/main/index.js
node scripts/core-ota-test/run.mjs launch
```

Expected: the shell log shows `core 1.0.0-core.2 rejected: size mismatch dist/main/index.js`, and it falls back to `previous` (1.0.0-core.1).

## 5. Boot failure rollback

Editing files inside `cores/<v>/` and changing their size is caught by the shell's size check (same as step 4), so instead publish a v4 that is correctly signed but whose renderer never mounts:

```bash
node scripts/core-ota-test/run.mjs v4 # index.html loads a single js resource that throws, seq 3, reload
node scripts/core-ota-test/run.mjs eval "window.electronAPI.invoke('rendererOta.checkNow')"
node scripts/core-ota-test/run.mjs eval "window.electronAPI.invoke('rendererOta.applyNow')"
```

Expected: within 3 seconds, `Core OTA rolled back {coldBoot: false, reason: 'load-timeout'}`, the pointer `blacklist` contains `1.0.0-core.3`,
and the window returns to the v3 renderer. Cold-start check: manually point `pointer.current` back at `1.0.0-core.3`, delete `boot.json`, and `launch`.
After 60 seconds, `Core OTA rolled back {coldBoot: true}` appears and the app relaunches to the previous version on its own.

## 6. Shell rescue (built-in core is broken)

```bash
R=release/core-ota-e2e/app/mac-arm64/azzar-core-ota-e2e.app/Contents/Resources
mv "$R/core.asar" "$R/core.asar.saved" # standalone E2E app only, move it back when done
# --dir packaging produces no app-update.yml; rescue uses it to find the feed address
printf 'provider: generic\nurl: http://127.0.0.1:8787/canary\n' > $R/app-update.yml
```

Place a `canary/appcast-arm64.xml` in `feed/` (the current buildVersion reports "already latest"; a higher version goes through Sparkle download and install; the package uses an EdDSA signature matching the test public key).

Expected: after `launch`, a rescue window and dialog appear, `userData/logs/shell-rescue.log` records the original error and the check results;
`boot.json` shows `builtin@1.0.0` with 3 failures, and the next launch skips loading core and goes straight to rescue. "Retry launch" clears the counter and truly reloads core.
A fake zip makes Sparkle report `Could not locate update bundle`; in that case the app should return to the failure dialog instead of hanging on "installing".

## Helpers

### A staged update replaced by a newer version

After completing step 1 (build) and starting the local feed, use `staged <b|c> <reload|relaunch>` to publish two signed updates based on the built-in v1. B is `1.0.0-core.10`, C is `1.0.0-core.11`; the renderer carries a `STAGED B/C` marker, and the relaunch version also prints its main-process log. Do not apply B first.

Start each group from the clean userData of the standalone test app (`reset` only applies to that test app), and verify the three combinations in the table below in order:

| B        | C        | Expected result when applying C                     |
| -------- | -------- | --------------------------------------------------- |
| reload   | reload   | The current process refreshes to C                  |
| relaunch | relaunch | Restart runs C directly; B is not a rollback target and is cleaned up |
| relaunch | reload   | The current process refreshes to C; B never runs, even on cold start after exit |

The third group is shown below as an example; for the other two, replace the mode argument of `staged`:

```bash
node scripts/core-ota-test/run.mjs kill
node scripts/core-ota-test/run.mjs reset
node scripts/core-ota-test/run.mjs staged b relaunch
node scripts/core-ota-test/run.mjs launch
# wait for the log to confirm B is staged; checking the same B again should keep the staged state
node scripts/core-ota-test/run.mjs eval "window.electronAPI.invoke('rendererOta.checkNow')"
node scripts/core-ota-test/run.mjs eval "window.electronAPI.invoke('rendererOta.getStatus')"
node scripts/core-ota-test/run.mjs state
node scripts/core-ota-test/run.mjs staged c reload
node scripts/core-ota-test/run.mjs eval "window.electronAPI.invoke('rendererOta.checkNow')"
node scripts/core-ota-test/run.mjs eval "window.electronAPI.invoke('rendererOta.getStatus')"
node scripts/core-ota-test/run.mjs state
node scripts/core-ota-test/run.mjs eval "window.electronAPI.invoke('rendererOta.applyNow')"
# the screenshot should show STAGED C reload; the main log should not show STAGED B relaunch
node scripts/core-ota-test/run.mjs eval --shot /tmp/core-ota-staged-c.png
node scripts/core-ota-test/run.mjs kill
node scripts/core-ota-test/run.mjs launch
node scripts/core-ota-test/run.mjs state
```

Record the B/C manifest trees, the state before and after staging, the pointer, the main log, and the process PID, and open the screenshot to confirm C is what actually loaded. For `relaunch -> reload`, applying should restore `current/previous` to the built-in baseline and `staged` to C before applying; for `relaunch -> relaunch`, `current` should point directly at C and `previous` should keep the version that actually ran, never B. This uses real IPC to accelerate the checks. It does not change the update logic, and it does not claim to cover the one-hour timer or the post-login notification UI.

`launch` passes `--remote-debugging-port=9333`. `run.mjs eval "<js>"` evaluates in the main window (`window.electronAPI.invoke('rendererOta.<applyNow|checkNow|getStatus>')`).
`run.mjs eval --shot <file.png>` screenshots the main window. `tamper` changes one line in `cores/1.0.0-core.2/dist/main/index.js`.
The onboarding page does not mount UpdateNotification, and the toast only appears after login; use `eval` to trigger IPC directly.
